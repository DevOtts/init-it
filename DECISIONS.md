# init-it decisions (do-it 1.0.1, CARD-A)

Each entry: the default taken, the recommendation, and a tag. Tags: `[DEFAULT]` picked because the spec was silent or ambiguous, `[SPEC-CONFLICT]` two spec lines could not both hold, `[SCOPE]` scope added or held back, `[ENV]` forced by the build environment.

| ID | Decision (default taken) | Recommendation | Tag |
|---|---|---|---|
| D-01 | status-write had no way to (a) update a role on a known `session_id` (T-A-03) or (b) create a missing `status.json` for init-it (T-A-07). init-it may not hand-edit the file and may not call `init` (plan-it only). Added both to status-write in the build-it PR: re-adding a known id with another role updates the role in place; `session add --create` (still init-it only) creates a minimal schema-1 board, no waves, `created_by: "init-it"`. plan-it's `status-from-plan` already uses `init --merge` on an existing file, so it adds the waves later. | Merge the build-it PR before releasing init-it. Until then init-it detects an old writer (exit 4 on create, a `role stays` warning on role change). | `[SPEC-CONFLICT]` |
| D-02 | INDEX layout: CARD-A wants the `Impl` column between Project and Session, old rows "blank", and T-A-12 wants legacy rows byte for byte. A 7-cell row under an 8-cell header shifts every cell left (Session would render under Impl). Default: when the first table has no `Impl` column, a new 8-column table is put above it (newest first) and new rows go there; the legacy table, header included, stays byte-identical. | Keep. Readers should key on the header row of each table (or on cell count: 8 = new, 7 = legacy). | `[SPEC-CONFLICT]` |
| D-03 | CARD-A says conclude-it "Step 2.6"; the conclude-it repo calls the ledger step "Step 2.5". Edited Step 2.5. | None. | `[DEFAULT]` |
| D-04 | Alias. CARD-A: "alias from the config dir name such as claudeanm". Fernando's ledger uses `claudeanm` for `~/.claude-anm` and `claudinho` for the default `~/.claude`. Default: `--alias`/`INIT_IT_ALIAS` wins; `.claude-<x>` maps to `claude<x>`; the default dir resolves only through `default_alias` in `~/.claude/init-it.json`; otherwise `"unknown"` plus a warning (never guessed). | Fernando: create `~/.claude/init-it.json` with `{"default_alias": "claudinho"}`. conclude-it's own rule (`.claude-work` → `work`) disagrees with the real ledger; align it in a later conclude-it change. | `[DEFAULT]` |
| D-05 | Default role when `--role` is omitted: `other` (the honest value; the script cannot know). | Callers (build-it, review-it) always pass the role. | `[DEFAULT]` |

| D-07 | Stale detection needs hours, the card `date` has only the day. The open card carries an extra header field `opened_at` (ISO UTC). | D-08 | Exit code 5 (new): `status.json` was updated but the card/INDEX write failed. CARD-A only says "a printed warning". Non-zero so callers notice; re-running heals. | Keep. | `[DEFAULT]` |
| D-09 | Unknown session id: status-write keys sessions on `session_id`, so all `"unknown"` registrations on one board collapse into one entry. Card idempotency for unknown ids matches only an open unknown-id card with the same alias, date and session name. | Accept; the warning tells the user why. | `[DEFAULT]` |
| D-10 | conclude-it's helper (`ledger-card.mjs`) is self-contained: it has its own copy of the card/INDEX format code instead of importing init-it, so conclude-it still works where init-it is not installed. The format is pinned by tests in both repos. | If the format changes, change both and both suites. | `[DEFAULT]` |

Sessions end before close because a closed board is frozen. A board with zero tasks (init-it created it, plan-it never ran) is NOT "all verified": it needs an owner note. | Keep the zero-task rule; it stops an unplanned folder being filed as done. | `[SCOPE]` |
